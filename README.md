# GST Reconciliation: GSTR-2B vs Purchase Register

Python project that reconciles a Tally-style **purchase register** against **GSTR-2B** and finds Input Tax Credit (ITC) at risk.

![Dashboard](dashboard.jpj)

## Problem Statement
A business can claim ITC only on purchase invoices that appear in its GSTR-2B. Manual matching of thousands of invoices is slow and error-prone. This project automates the matching, classifies every invoice, and ranks the suppliers who put the ITC at risk.

## Dataset
Fully **synthetic** (no real client data), generated by `src/generate_gst_data.py`.

| File | Rows | Description |
|------|------|-------------|
| `data/purchase_register.xlsx` | 1,470 | Books side (Apr-Sep 2026, 40 suppliers) |
| `data/gstr2b.xlsx` | 1,317 | Government portal side |
| `data/answer_key.xlsx` | n/a | Planted errors, used to check accuracy |

Errors planted on purpose: invoice-number format differences, GSTIN typos, duplicate entries, value mismatches, rounding differences, invoices missing in 2B, invoices missing in books, and 3 suppliers who never filed.

## Approach
1. **Clean**: uppercase and trim GSTIN, strip symbols from invoice numbers, standardise mixed date formats.
2. **Flag duplicates** in books (same GSTIN, invoice no and amount).
3. **Round 1, exact key** (`GSTIN + cleaned invoice no`): Matched if total tax differs by Rs 2 or less, else Value Mismatch.
4. **Round 2, GSTIN typo**: same invoice number and value, GSTIN differs by 1-2 characters.
5. **Round 3, invoice number differs**: same GSTIN and value, similar invoice number (fuzzy match).
6. **Round 4/5**: leftovers become *In Books Only (ITC at Risk)* or *In 2B Only (Unrecorded Purchase)*.
7. Export a multi-sheet Excel report and show it in a Streamlit dashboard.

## Results

| Status | Invoices | % |
|--------|---------:|--:|
| Matched | 1,199 | 79.2 |
| Probable Match (GSTIN typo) | 14 | 0.9 |
| Probable Match (Invoice no differs) | 4 | 0.3 |
| Value Mismatch | 56 | 3.7 |
| In Books Only (ITC at Risk) | 183 | 12.1 |
| In 2B Only (Unrecorded Purchase) | 44 | 2.9 |
| Duplicate Entry in Books | 14 | 0.9 |

| KPI | Value |
|-----|------:|
| ITC as per books | Rs 4.01 crore |
| ITC as per GSTR-2B | Rs 3.62 crore |
| **Total ITC at risk** | **Rs 48.1 lakh (12.0% of books ITC)** |
| Unrecorded purchases (possible missed ITC) | Rs 8.8 lakh |
| Match rate | 83.6% |

### Key Findings
- **Rs 48.1 lakh of ITC is at risk**, mostly from invoices missing in GSTR-2B.
- The **top 3 suppliers account for about 61% of the risk**, so following up with a few suppliers recovers most of it.
- **127 invoices belong to 3 suppliers who appear to have never filed GSTR-1**; these need escalation or a payment hold.
- **14 duplicate entries (Rs 3.1 lakh)** were booked twice and would have overstated ITC.
- All planted errors were detected; counts match `answer_key.xlsx`.

## Tech Stack
Python (pandas, openpyxl, difflib), Streamlit, Plotly, Excel

## How to Run
```bash
pip install pandas openpyxl streamlit plotly
cd data && python ../src/generate_gst_data.py && cd ..   # optional: regenerate data
python src/reconcile.py
streamlit run src/dashboard.py
```
Output: `output/reconciliation_output.xlsx` with sheets `KPIs`, `Status Summary`, `Supplier Risk`, `Reconciliation`, `Exceptions`.
